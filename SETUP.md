# InstaCloud setup guide

This guide covers local development with and without Docker, the third-party
accounts required by InstaCloud, database migrations, and a basic production
deployment checklist.

## What you need

- Git
- Node.js 22 or newer for a non-Docker setup
- npm (included with Node.js)
- Docker Desktop or Docker Engine + Docker Compose for a Docker setup
- An InstaCloud repository checkout

The repository is a monorepo:

```text
apps/api   Express API and background worker
apps/web   Next.js web application
supabase/  PostgreSQL migrations
```

## 1. Create the required accounts

The application uses hosted services for authentication/PostgreSQL, Redis, and
image storage. Create one account for each service below. Free tiers are
sufficient for local development, but check each provider's current limits.

### Supabase

1. Open [supabase.com](https://supabase.com/) and create an account.
2. Create a new project.
3. Choose a strong database password and save it in a password manager.
4. Open **Project Settings → API** and copy:
   - **Project URL** as `SUPABASE_URL`
   - **Publishable/anon key** as `SUPABASE_ANON_KEY`
5. Open **Project Settings → Database → Connect**.
6. Select the **Transaction pooler** connection string (port `6543`).
7. Replace the password placeholder in that string and save it as
   `DATABASE_URL`.

Use the publishable/anon key in this project. Never put the Supabase
`service_role` or secret key in `.env`, browser code, Docker build arguments, or
source control.

For easy local registration, open **Authentication → Providers → Email** and
temporarily disable email confirmation. Re-enable confirmation before a public
production launch.

### Upstash Redis

1. Open [upstash.com](https://upstash.com/) and create an account.
2. Create a Redis database.
3. Choose a region close to the API deployment.
4. Open the database **Connect** page.
5. Copy the Redis URL intended for Node.js/ioredis and save it as `REDIS_URL`.

The URL normally begins with `rediss://`. Keep the full URL, including its
password and port. Do not use the REST URL in `REDIS_URL`; this application
uses the Redis protocol through ioredis and BullMQ.

For Docker-only local Redis, the included Compose profile can be used instead:

```bash
docker compose --profile local-redis up redis
```

Then use:

```env
REDIS_URL=redis://redis:6379
```

### Cloudinary

1. Open [cloudinary.com](https://cloudinary.com/) and create an account.
2. Open the Cloudinary **Dashboard**.
3. Copy the following values:
   - **Cloud name** as `CLOUDINARY_CLOUD_NAME`
   - **API Key** as `CLOUDINARY_API_KEY`
   - **API Secret** as `CLOUDINARY_API_SECRET`

The browser uploads images directly using a signed request generated by the
API. Keep `CLOUDINARY_API_SECRET` server-side only.

### Optional services

These services are not required to run the app:

- [Resend](https://resend.com/) for welcome emails:
  `RESEND_API_KEY` and `RESEND_FROM`
- [Sentry](https://sentry.io/) for API and worker error reporting:
  `SENTRY_DSN`
- Grafana Cloud or another Prometheus-compatible service for the `/metrics`
  endpoint. Set `METRICS_TOKEN` to protect metrics access.

## 2. Create the environment file

From the repository root:

```bash
cp .env.example .env
```

Open `.env` and fill in the required values:

```env
SUPABASE_URL=https://YOUR-PROJECT-REF.supabase.co
SUPABASE_ANON_KEY=your-publishable-or-anon-key
DATABASE_URL=postgresql://postgres.YOUR-PROJECT-REF:YOUR_PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres

REDIS_URL=rediss://default:YOUR_PASSWORD@YOUR-ENDPOINT.upstash.io:6379

CLOUDINARY_CLOUD_NAME=your-cloud-name
CLOUDINARY_API_KEY=your-api-key
CLOUDINARY_API_SECRET=your-api-secret

PORT=4000
WEB_ORIGIN=http://localhost:3000
API_PUBLIC_URL=http://localhost:4000
TRUST_PROXY=false
INLINE_WORKER=false
```

The root `.env` is loaded by the API and by the Next.js configuration. Never
commit it. The repository's `.gitignore` already excludes environment files.

## 3. Run without Docker

### Install dependencies

From the repository root:

```bash
npm install
```

### Run the database migration

The migration creates the application tables, indexes, triggers, and related
database objects in Supabase:

```bash
npm run db:migrate
```

The migration is safe to run again after a failed setup or when checking a
new environment.

### Start the development stack

```bash
npm run dev
```

This starts:

| Process | Address |
|---|---|
| API | http://localhost:4000 |
| Worker | background process |
| Web | http://localhost:3000 |

Open [http://localhost:3000](http://localhost:3000) in a browser.

To run individual processes instead:

```bash
npm run dev -w @insta/api
npm run dev:worker -w @insta/api
npm run dev -w @insta/web
```

### Verify the API

```bash
curl http://localhost:4000/health
```

The API should return a successful health response. If the web app cannot
connect, check that `API_PUBLIC_URL` points to the API address and that
`WEB_ORIGIN` matches the browser origin exactly.

## 4. Run with Docker

Docker uses the Node.js and dependency versions declared by the Dockerfiles.
You do not need Node.js installed locally for this workflow.

### Build the images

From the repository root:

```bash
docker compose build
```

### Run the database migration

The migration command is intentionally run separately so it completes before
the long-running services start:

```bash
docker compose run --rm api node apps/api/dist/scripts/migrate.js
```

### Start the application

```bash
docker compose up
```

The Compose services are:

| Service | Purpose | Address |
|---|---|---|
| `api` | Express API | http://localhost:4000 |
| `worker` | BullMQ background jobs | no public port |
| `web` | Next.js application | http://localhost:3000 |

Open [http://localhost:3000](http://localhost:3000).

Run in the background:

```bash
docker compose up -d
docker compose logs -f web
```

Stop the stack:

```bash
docker compose down
```

### Use the local Redis Compose profile

If you do not want to create an Upstash account for local development:

```bash
docker compose --profile local-redis up --build
```

Set this in `.env`:

```env
REDIS_URL=redis://redis:6379
```

Supabase and Cloudinary are still required unless you replace those
integrations in the application.

## 5. First browser test

1. Open the web app.
2. Register an account.
3. If email confirmation is enabled in Supabase, confirm the email first.
4. Open a second browser profile or private window and register a second user.
5. Follow the other user.
6. Upload an image and add a caption.
7. Like the post and add a comment.
8. Check that notifications appear in the bell menu.

Cloudinary uploads happen from the browser, so a failed upload usually means
one of the Cloudinary values is incorrect or the API is not reachable from the
browser.

## 6. Production configuration

For production, use separate accounts/projects or databases from local
development. At minimum:

- Enable Supabase email confirmation.
- Use a verified email sender with Resend.
- Set `TRUST_PROXY=true` when the API is behind a reverse proxy.
- Set `WEB_ORIGIN` to the exact HTTPS web URL.
- Set `API_PUBLIC_URL` to the exact HTTPS API URL.
- Use `rediss://` for hosted Redis.
- Store secrets in the hosting provider's secret manager.
- Do not expose `DATABASE_URL`, `CLOUDINARY_API_SECRET`, or service-role keys
  to the browser.
- Move refresh-token storage from `localStorage` to an HttpOnly cookie before
  handling sensitive production traffic.

### Azure Container Apps overview

The included Dockerfiles can be deployed as three Container Apps:

1. Build and push `apps/api/Dockerfile` as the API image.
2. Run `node apps/api/dist/scripts/migrate.js` once against Supabase.
3. Run the API image with its default command on port `4000`.
4. Run the same API image with
   `node apps/api/dist/worker.js` as the worker.
5. Build and push `apps/web/Dockerfile` with
   `--build-arg API_PUBLIC_URL=https://your-api-host`.
6. Run the web image on port `3000`.
7. Add all environment variables to Azure Container App secrets and
   environment settings, not to the image.
8. Allow WebSocket traffic to the API because live notifications use `/ws`.

Example image commands:

```bash
docker build -f apps/api/Dockerfile -t YOUR_REGISTRY/instacloud-api:latest .
docker push YOUR_REGISTRY/instacloud-api:latest

docker build \
  -f apps/web/Dockerfile \
  --build-arg API_PUBLIC_URL=https://your-api-host \
  -t YOUR_REGISTRY/instacloud-web:latest \
  .
docker push YOUR_REGISTRY/instacloud-web:latest
```

`API_PUBLIC_URL` is embedded into the Next.js browser bundle at build time.
Rebuild the web image whenever the public API hostname changes.

## 7. Troubleshooting

### `npm run db:migrate` cannot connect

- Confirm the Supabase database password is URL-encoded if it contains
  characters such as `@`, `:`, `/`, or `#`.
- Confirm `DATABASE_URL` uses the Transaction pooler on port `6543`.
- Confirm the Supabase project is running.

### Redis connection errors

- Use the Upstash Redis/ioredis URL, not the REST URL.
- Keep the `rediss://` prefix for TLS.
- For Compose Redis, use `redis://redis:6379` from inside the containers.

### CORS errors in the browser

Set `WEB_ORIGIN` to the complete browser origin, including the scheme and
port:

```env
WEB_ORIGIN=http://localhost:3000
```

Do not add a trailing path such as `/login`.

### The web app calls the wrong API URL

`API_PUBLIC_URL` is baked into the Next.js build. Update `.env` and rebuild:

```bash
docker compose build web
```

For a non-Docker run, restart the Next.js development server after changing
the variable.

### Worker jobs do not run

Confirm both the API and worker use the same `REDIS_URL`. In Docker, inspect:

```bash
docker compose logs -f worker
```
